3) MODELLO DI SICUREZZA v10.4 (IL CUORE — NON ROMPERE)
--------------------------------------------------------------------------------
a) LOGIN OBBLIGATORIO ad ogni avvio, SEMPRE SOLO PASSWORD:
   - checkLoginRequired() mostra SEMPRE la schermata di accesso
     (niente apertura automatica, niente "sessione valida N giorni").
   - Il campo "codice dispositivo" NON è nella schermata di accesso:
     è nascosto sotto il link "📱 Primo su questo dispositivo?"
     (#login-code-wrap) e serve UNA SOLA volta per collegare un
     dispositivo nuovo.
   - Ordine di verifica in doLogin() (NON cambiarlo):
     1) record locale: a.pass (PBKDF2 in 'immocrm_auth') oppure
        localPass/_localPass (hash semplice legacy, poi aggiornato);
     2) cloud: ImmoSync.unlockFromCloud(password) — la password giusta
        (quella PIÙ RECENTE, anche se cambiata su un altro dispositivo)
        deriva la chiave da password + sale condivisa e decifra
        l'archivio: 'ok' → login; 'badkey' → rifiuto definitivo;
        'noarchive'/'error' → si passa al punto 3;
     3) record del codice (solo se un codice è stato incollato):
        verificaConHash(dec.pass, password) — ripiego offline.
   - Se è presente un codice, apriConCodice() lo applica PRIMA della
     verifica: è il "permesso" (token+archivio+sale) che permette al
     dispositivo nuovo di raggiungere il cloud.
   - Il record password vive ANCHE in DB.settings.passRec (dentro i
     dati sincronizzati, quindi cifrato): a ogni pull,
     applicaDbRemoto() aggiorna il locale a.pass da passRec.
     Se tocchi il cambio password, aggiornare passRec è OBBLIGATORIO
     (aggiornaHashPassword() già lo fa).
   - RECUPO PASSWORD: "🔑 Password dimenticata?" (mostraRecupero /
     faRecupero) → risposta alla DOMANDA SEGRETA (auth.question /
     auth.answer, impostate in doSetup) → nuova password → nuovo record
     PBKDF2 + ImmoSync.rekeyWithPassword() (ricifra l'archivio cloud con
     la nuova password, stessa sale). Recupero via e-mail/SMS: NON
     implementato (servirebbe un backend + servizio a pagamento, es.
     SendGrid/Twilio): eventuale futura feature, da progettare con un
     endpoint/Worker, non in app.js.
   - ANTI-CONGELAMENTO (v10.4.1): le finestre "recupero password" e
     "cambia password" mostrano un progresso passo-passo e il tasto torna
     SEMPRE cliccabile (try/finally + scatto di sicurezza a 120 s). Tutte
     le richieste di rete a GitHub in sync.js hanno un timeout (GH_TIMEOUT,
     default 20 s, _internal.ghTimeout per i test): una rete morta/lenta
     NON deve mai lasciare una finestra congelata — è la causa storica del
     "si blocca tutto" riferito dall'utente. Nuove fetch → SEMPRE timeout.
   - Lockout: 3 errori → blocco temporaneo. Auto-lock per inattività
     (lockMin, default 15 min) → bloccaApp().
b) CHIAVE DI CIFRATURA CONDIVISA:
   - Stessa password + stessa SALE = stessa chiave su tutti i dispositivi.
   - La sale resta STABILE: unlockWithPassword usa SEMPRE keepSalt:true
     (o una sale esplicita). Mai sale random dopo che una chiave esiste:
     è la causa storica del "triangolo giallo" sul secondo dispositivo.
   - La sale viaggia nell'archivio cloud (env.cipher.salt) e nel codice.
   - Dopo il login, se hasMasterKey() è false: doLogin chiama
     ensureMasterKey(password) (ricava la chiave dall'archivio), non una
     chiave random.
   - La password di accesso resta in memoria (variabile _cloudPass in
     app.js) SOLO per l'auto-sblocco della chiave cloud; va azzzerata a
     logout e a blocco (già fatto: non rimuovere).
c) CODICE DISPOSITIVO (v3) — formato ESATTO:
     IMMOCRM1. + base64( JSON )
     JSON = { v:3,
              m: 'gist'|'rest'|'off',   // modalità cloud
              g: gistId,
              t: tokenGitHub,
              e: 1|0,                    // cifratura attiva?
              r: restUrl,                // (solo modalità rest)
              s: saltB64,                // SALE master condivisa
              h: {salt, iter, hash} }    // hash PBKDF2 della password
   - v10.4: NON contiene più k (la chiave AES grezza). Nella v10.3 la
     conteneva e questo era un buco di sicurezza: il codice da solo
     bastava a decifrare il cloud senza password. LA CHIAVE SI RICAVA
     SEMPRE da password + sale condivisa → non va mai scambiata.
     I vecchi codici v2 (con k) restano leggibili (importMaster).
   - È un "permesso di collegamento": contiene il token GitHub
     (bearer!) → mai loggarlo, mai in repo, mai in file pubblici.
   - Si genera SOLO nel dispositivo utente (sync.connectCode({pass})),
     si mostra automaticamente al primo collegamento e su richiesta
     (Impostazioni → Sincronizzazione → "Genera codice dispositivo").
   - Si applica in due posti: schermata di accesso (link "Primo su
     questo dispositivo?" → campo #login-code → doLogin) e Impostazioni
     (usaCodiceSync).
d) FUNZIONI sync.js pubbliche da conoscere:
   boot, setStorageKey, track, rebaseline/adopt, mirror, onLocalChange,

f) v10.5 — TRE BLOCCHI NUOVI (non romperli):
   - ALLARMI SCADENZE (app.js, sezione "ALLARMI SCADENZE"):

4) INVARIANTI (se una modifica le viola: STOP e avvisami)
--------------------------------------------------------------------------------
 1. Login richiesto a ogni avvio, e il login è sempre (solo) password.
 2. Cifratura ATTIVA per default; nessun push in chiaro se encrypt=true
    e la chiave manca (il blocco c'è in push(): non rimuoverlo).
 3. Nessuna sale random dopo che una chiave esiste (keepSalt).
 4. Nessuna informazione segreta (token, chiavi, password, codici)
    nel repo o nei file pubblici.
 5. npm test al 100% prima di ogni commit che tocca logica.
 6. sw.js: ogni volta che cambia index/app/sync → bumpare la costante
    CACHE ('immocrm-shell-vN'), altrimenti gli utenti restano sulla
    vecchia versione.
 7. Le stringhe di versione devono muoversi insieme: <title> in
    index.html · .login-version in index.html · console.log in app.js
    (boot) · info card in renderImpostazioni · esportaBackup.
 8. Il codice dispositivo non contiene la chiave grezza (formato v3):
    la chiave si ricava da password + sale condivisa. Se reintroduci
    un campo "k" in connectCode: STOP, è un buco di sicurezza.
 9. Cambiando la password bisogna aggiornare: a.pass locale,
    DB.settings.passRec (sincronizzato) e l'archivio cloud
    (rekeyWithPassword o sblocco+push). Manca uno dei tre → altri
    dispositivi bloccati (bug della v10.3, corretto in v10.4).

9) TROUBLESHOOTING (errori già incontrati, non ricaderci)
--------------------------------------------------------------------------------
- Nel test multi-dispositivo (tests/run.cjs) i fetch RAW al server
  GitHub finto servono l'header { Authorization: 'Bearer <token>' },
  altrimenti rispondono 401 (il Gist è privato).
- In jsdom, sync.js e app.js vengono INLINE in <script>: l'istanza
  ImmoSync della window è SEPARATA da quella Node dei test.
- In jsdom le funzioni top-level di app.js sono su window (window.xxx);
  i let/const top-level NO: per quelli usa win.eval('nome(...)').
- WebCrypto (subtle) serve HTTPS: su http (non localhost) la cifratura
  non parte — l'app deve poter funzionare in "Non cifrato" senza crash.
- app.js è un monolite senza modulo: non "rifattorizzarlo" in moduli
  senza un'espressa richiesta.
- Se un edit fuzzy fallisce con "Context not found": ricopia l'ancora
  ESATTA dal file (grep -n) invece di ridigitarla.
- npm test → "Cannot find module 'jsdom'": ridai npm install.
